# Case Review Automation
## 工单自动分类与运营分析工作流

本项目源于实际业务中的工单整理与运营分析需求，将数据导入、规则分类、AI 辅助复核、人工确认和报告输出连接为一条工作流。

项目重点包括：
- 将业务判断整理为明确的分类规则。
- 保留初始分类与复核结果，记录修改依据。
- 在结果回写前进行数据与分类校验。
- 通过可视化统计和报告支持运营分析。

## 业务背景

在企业服务运营中，运营人员需要定期整理业务系统导出的工单数据，分析需求来源、活动类型和业务主题，并形成统计报告。

这项工作包含多层判断：记录服务于内部协作还是外部需求、当前属于哪种处理活动，以及具体涉及哪些业务主题。这些维度的适用范围不同，需要分别定义规则。

部分记录可以依据明确规则分类，另一些则存在描述不完整、关键词歧义或多个主题同时出现的情况，需要补充上下文并进行复核。分类结果还要继续用于数据汇总、图表制作与报告交付。

## 项目目标

- **统一分类口径：** 将业务经验整理为明确的分类维度、判断顺序和例外条件，提高结果的一致性。
- **减少重复操作：** 将数据整理、规则分类、结果更新和报告生成连接起来，减少反复复制与手动处理。
- **支持疑难案例复核：** 结合独立 AI 工具与人工判断处理不明确的记录，保留初始分类、最终结果及关键词依据。
- **保障结果更新的一致性：** 在复核结果回写前检查记录对应关系、标签合法性和数据状态。
- **支持运营分析：** 将确认后的分类结果转化为可视化统计与报告，并明确主主题和多标签统计的计数方式。


### 工作流程

#### 1. 数据导入与整理

支持导入 Excel 或 CSV 文件，将表格中的记录编号、标题、描述等字段对应到工具中，识别缺少编号、重复记录等情况，为后续分类准备数据。

#### 2. 设置分类维度与标准

用户根据业务需求，定义一个或多个分类维度，并为各维度下的具体分类设置分类名称、分类原则、优先级和组合方式。

不同维度分别判断，同一条记录可以在多个维度下获得分类结果。

#### 3. 初步分类

通过可执行规则处理能够明确判断的记录，生成初步分类结果，并保留匹配依据。

需要结合业务语义判断、缺少依据或存在冲突的记录，进入后续复核环节。

#### 4. AI 辅助复核与人工确认

将待复核记录及分类标准导出，在支持 MCP 的独立 AI 工具中，通过已配置并获授权的 MCP 服务连接相关数据平台，按需读取与当前记录有关的补充上下文。

AI 结合分类原则、原始记录和补充信息进行分析，提出分类建议，再由人工确认。

初始分类与复核结果分别保留，便于比较修改并查看分类依据。对于上下文不足或仍存在冲突的分类，允许留空，保留待确认状态。

#### 5. 复核结果校验与更新

导回复核结果时，检查记录编号是否对应、分类是否属于用户定义的范围、组合方式是否符合设置，以及数据是否已发生变化。

通过校验后更新结果；存在冲突或异常的记录保留待处理，避免直接覆盖。

#### 6. 可视化分析与报告输出

按照用户定义的分类维度汇总结果，生成分类分布和统计图表，并支持表格、PPT 与 PDF 导出。

对于允许多标签的维度，提供两种统计口径：

- **主分类统计：** 每条记录计入一个主分类。
- **全部分类统计：** 统计每条记录的全部有效分类，一条记录可以计入多个分类。

统计时注明计数方式，并单独展示待确认记录，帮助使用者理解分类结果与统计数量之间的关系。

### 分类设计

#### 按业务定义分类维度

分类维度表示“按什么角度分类”，具体分类表示该维度下可以使用的标签。

用户可以根据业务需求定义一个或多个维度。例如：

| 应用场景 | 分类维度示例 | 具体分类示例 |
| --- | --- | --- |
| 需求整理 | 需求类型 | 咨询、申请、反馈 |
| 内容管理 | 内容形式 | 文案、图片、视频 |
| 资料归档 | 资料类别 | 操作指南、参考资料、常见问题 |

以上仅为通用示例，用户可以根据自己的业务重新定义。

同一条记录可以在不同维度下分别分类，各维度的分类标准独立管理。

#### 可配置的分类标准

每个具体分类包含以下四项设置：

| 设置项 | 说明 |
| --- | --- |
| 分类名称 | 定义最终输出的分类标签 |
| 分类原则 | 说明分类的业务含义，以及什么情况下应归入该类 |
| 优先级 | 多个分类同时符合时，决定优先采用哪一类，支持通过排序调整 |
| 组合方式 | 设置该分类单独使用，或允许与指定分类同时使用 |

分类原则用于指导人工及 AI 辅助判断；优先级和组合方式用于确定同一维度内多个分类同时符合时的处理方式。

程序自动分类由可执行规则完成。需要进一步理解业务语义的记录，进入 AI 辅助复核环节；在相关 MCP 服务可用时，AI 可以获取补充上下文，辅助完成判断，并由人工确认最终结果。

整体工作流将规则分类、MCP 上下文获取、AI 辅助分析与人工确认相结合，使分类既有明确标准，也能参考实际业务信息。


## 安装与使用

### 1. 运行环境

本项目是运行在 SharePoint 页面上的浏览器用户脚本，需要：

- 浏览器脚本管理器：[Violentmonkey 官方安装页面](https://violentmonkey.github.io/get-it/)，根据使用的浏览器选择对应版本。
- 自己有访问和编辑权限的 SharePoint 站点及列表。
- 独立 AI 工具，用于复核需要理解业务语义的记录。

脚本不内置模型接口或 MCP 客户端。AI 复核在独立工具中进行，通过文件导出与回填衔接分类流程。

### 2. 安装脚本与配置列表

下载本仓库中的 `case_review_public_3.3.7.user.js`，导入 Violentmonkey。

编辑脚本开头的 `PUBLIC_SETTINGS`，填写自己的配置：

```javascript
const PUBLIC_SETTINGS = {
    siteUrl: 'https://your-tenant.sharepoint.com/sites/your-site',
    listName: 'Your List',
    subjectField: 'case subject',
    classificationField: 'classification',
};
```

| 配置项 | 填写内容 |
| --- | --- |
| `siteUrl` | SharePoint 站点地址，不填写包含 `/Lists/...` 的列表页面地址 |
| `listName` | 列表名称 |
| `subjectField` | 存放工单标题的列名 |
| `classificationField` | 存放分类结果的列名 |

列表需要以下字段：

| 字段 | 用途 | 建议类型 |
| --- | --- | --- |
| `Title` | 存放唯一工单编号 | 单行文本 |
| `case subject` | 存放工单标题 | 单行或多行文本 |
| `classification` | 存放分类结果 | 纯文本多行 |

如果使用不同的标题列或分类列名称，需要同步修改配置。三个字段应分别使用不同的列。

保存脚本，在同一浏览器登录 SharePoint，打开配置站点下的列表页面。站点和列表配置为空时，脚本不会显示操作按钮或发送平台请求。

### 3. 配置分类标准

编辑脚本中的 `CLASSIFICATIONS`，每项分类包含四个设置：

| 设置项 | 含义 |
| --- | --- |
| `name` | 分类名称 |
| `principle` | 分类原则及适用条件 |
| `priority` | 优先级，正整数，数值越小越优先；相同时按配置顺序 |
| `combinations` | 允许同时使用的其他分类名称，空数组表示单独使用；组合需双方明确允许 |

示例：

```javascript
const CLASSIFICATIONS = [
    {
        name: '资料查询',
        principle: '标题包含“使用指南”或“操作说明”',
        priority: 1,
        combinations: [],
    },
    {
        name: '权限申请',
        principle: '标题包含“开通权限”',
        priority: 2,
        combinations: [],
    },
    {
        name: '交付跟进',
        principle: '已经交付的资料无法使用，需要进一步处理。',
        priority: 3,
        combinations: [],
    },
];
```

程序自动执行完整、明确的文字条件，例如 `标题包含“使用指南”或“操作说明”`。

需要理解业务语义的原则交给独立 AI 工具复核，程序不会自行从自然语言原则中猜测关键词。优先级用于处理符合条件的分类，不会直接将所有记录归入最高优先级类别。

### 4. AI 与 MCP 配置

将初始分类表、AI Rules 导出的分类标准和相关上下文提供给独立 AI 工具，复核后由人工确认。

如需从工作平台获取补充上下文，可以在支持 MCP 的 AI 工具中配置对应平台的 MCP 服务，并授权访问所需数据。具体连接方式取决于所选 AI 工具和数据平台。

MCP 是可选的上下文获取方式。未配置 MCP 时，也可以手动提供补充材料；本仓库的 `examples/测试上下文.txt` 可用于练习复核流程。

参考：[MCP 官方连接示例](https://modelcontextprotocol.io/docs/develop/connect-local-servers)。该示例以本地文件服务为例，工作平台的连接需参考对应服务的配置说明。

### 5. 操作顺序

1. **Import 1**：导入原始 Excel，执行明确的文字条件，生成初始分类并写入列表。
2. **Export Excel**：导出初始分类及程序匹配依据。
3. **AI Rules**：导出当前分类标准与 AI 回填要求。
4. **AI 辅助复核与人工确认**：将初始表和规则包交给独立 AI 工具，按需补充上下文，完成复核并由人工确认。
5. **Import 2**：导入确认后的最终表，经校验后更新分类结果。
6. **Dashboard**：查看分类统计，并导出表格、PPT 或 PDF。

回填时应遵循 AI Rules 中的表格格式，保留初始分类与 `Script evidence`。将分类修改为非空结果时，应填写简短的 `AI evidence`。

最终分类留空会清除该记录当前的分类结果。尚未复核的记录应保留初始分类。修改分类标准后，应重新导出规则包与初始表。

**Clear All** 会在页面确认后删除配置列表中的全部记录，请仅在独立测试列表中验证此操作。

### 6. 测试样例

建议先在独立的 SharePoint 测试列表中，保留默认分类配置，使用以下文件验证：

| 文件 | 用途 |
| --- | --- |
| [测试工单.xlsx](examples/测试工单.xlsx) | 6 条虚构原始记录，用于 Import 1 |
| [测试AI回填.xlsx](examples/测试AI回填.xlsx) | 人工编写的模拟复核结果，用于 Import 2 |
| [测试上下文.txt](examples/测试上下文.txt) | 虚构的补充信息，可用于 AI 复核练习 |
| [测试预期.md](examples/测试预期.md) | 测试步骤及各记录的预期结果 |

默认示例完成回填后，预期共 6 条记录：资料查询 3 条、权限申请 1 条、交付跟进 1 条、待复核（Needs review）1 条。

测试回填文件不是实际模型输出。修改默认分类后，需要同步调整配套回填文件。

现有验证基于模拟环境，真实 SharePoint 权限、MCP 连接和模型判断效果需要在使用者自己的环境中确认。

## 个人贡献与验证范围

在原项目中，我负责梳理人工分类流程与业务判断标准，并借助 AI 辅助编写、调试和迭代脚本。对于需要结合上下文理解的疑难记录，在独立 AI 工具中进行复核，并通过人工确认持续调整分类标准。

公开版保留数据导入、规则分类、AI 复核回填和统计导出流程，移除原业务的专属规则与环境配置，使用虚构数据展示使用方式。

目前已完成 13 项自动化测试，并在模拟浏览器与 SharePoint 响应环境中验证导入、分类、回填及报告导出。真实 SharePoint 环境和 MCP 连接仍需使用者自行配置验证。
